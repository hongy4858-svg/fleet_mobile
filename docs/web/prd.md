# PRD: 기업 차량 운영 관리 및 친환경차 전환 경제성 분석 시스템

## 1. 프로젝트 개요
- **프로젝트명**: 기업 차량 운영 관리 및 친환경차 전환 경제성 분석 시스템 (Fleet Operation & Green Transition Economic Evaluation System)
- **과제 성격**: 산업공학과 데이터베이스 및 경제성공학(Engineering Economy) 융합 실무 과제
- **핵심 목표**: 기업이 보유한 업무용 차량의 일상적인 운행, 에너지(주유/충전), 정비 이력을 체계적으로 관리하고, 기존 내연기관/노후 차량을 계속 유지하는 대안과 최신 친환경 차량(전기차/수소차/하이브리드 등)으로 교체하는 대안 간의 수명주기 총비용을 현재가치(Present Worth / Net Present Value of Cost) 기준으로 객관적으로 비교·분석하는 웹 애플리케이션 구축.

---

## 2. 사용자 및 배경
### 2.1 주요 사용자
1. **기업 차량 및 자산 관리자 (총무팀/물류운영팀)**:
   - 보유 차량의 일상 운행거리, 주유/충전 비용, 정비 이력을 기록하고 차량별 유지관리 현황을 추적.
   - 노후 차량 교체 시기 도래 시, 의사결정권자에게 제출할 합리적인 비용 비교 보고서가 필요.
2. **ESG 및 친환경 전환 기획자 (경영기획팀)**:
   - 기업 탄소중립 계획에 따른 친환경차 전환 시, 예산 제약 내에서 경제성이 확보되는 교체 시나리오 검토.

### 2.2 해결하고자 하는 문제
- 차량 관리와 비용 데이터가 엑셀 등에 파편화되어 차량별 실제 km당 운영단가를 파악하기 어려움.
- 차량 교체 시 "단순 신차 가격"만 고려하거나, "미래 운영비 절감액"을 할인율 없이 단순 합산하여 잘못된 의사결정을 내리는 오류 방지.
- 과거 차량 구매가격(매몰비용)을 의사결정에 잘못 반영하거나, 감가상각비와 신차 구매비를 이중 계상하는 경제성 분석 오류 해결.

## 3. 핵심 기능 요구사항

### 3.1 대시보드 (Dashboard)
- **KPI 지표 요약**:
  - 총 등록 차량 수 (연료별 분포 포함)
  - 선택 기간 동안의 총 주행거리 (km)
  - 선택 기간 동안의 총 에너지비용(주유/충전비) 및 총 정비비용 (원)
- **기간 필터링**: 전체, 최근 1개월, 3개월, 6개월, 1년, 사용자 지정 기간.
- **차량별 운영 효율 비교**:
  - 차량별 km당 운영비용((에너지비+정비비)/주행거리) 막대 차트 및 랭킹 테이블.
  - 주행거리 0km 시 처리: 0으로 나누기 방지 및 "기록 없음 / 계산 불가" 안내.

### 3.2 차량 관리 (Vehicle Management)
- **차량 마스터 CRUD**: 차량 등록, 목록 조회, 상세 조회, 수정, 삭제.
- **필수 항목**: 차량번호, 차량명(모델명), 연료 종류, 구매일, 구매가격, 공인 기준 연비, 메모.
- **연료 종류 지원**: 가솔린, 디젤, 하이브리드, 전기(EV), 수소(FCEV) 5종.
- **데이터 무결성**:
  - 차량번호 중복 등록 방지.
  - 연관된 운영 기록(운행, 주유, 정비)이 존재하는 차량 삭제 시, 즉시 삭제되지 않고 연관 기록 건수와 영향도를 경고하며 최종 확인을 거친 후 삭제(Cascade 또는 차단).

### 3.3 운행 및 비용 기록 관리 (Operation Logs)
- 차량 선택 필터 및 기간 필터 제공.
- **A. 운행 기록 (Trip Logs)**: 차량, 운행일자, 주행거리(km), 운행 목적/메모 CRUD.
- **B. 주유·충전 기록 (Energy Logs)**:
  - 차량, 주입일자, 주입량, 총 결제금액(원), 주유소/충전소명 및 메모 CRUD.
  - **단위 자동 매핑**:
    - 가솔린/디젤/하이브리드 $\rightarrow$ `L` (리터), 단가 `원/L`
    - 전기 $\rightarrow$ `kWh`, 단가 `원/kWh`
    - 수소 $\rightarrow$ `kg`, 단가 `원/kg`
- **C. 정비 기록 (Maintenance Logs)**: 차량, 정비일자, 정비항목(오일 교환, 타이어 교체, 정기점검 등), 정비비용(원), 메모 CRUD.

### 3.4 유지 vs 교체 경제성 비교 (Replacement Economic Analysis)
- **대안 비교 프레임워크**:
  - **대안 A (기존 차량 유지)**: 현재 보유 차량 선택 $\rightarrow$ 향후 운영비 및 잔존가치 평가.
  - **대안 B (신규 차량 교체)**: 교체 후보 차량 선택(또는 신규 등록) $\rightarrow$ 순 취득원가(구매가+부대비용-보조금-기존차 매각가), 향후 운영비, 잔존가치 평가.
- **공통 분석 조건**:
  - 분석 기간 $N$ (년)
  - 연간 예상 주행거리 (km/년)
  - 연간 할인율 $i$ (%/년, 0% 및 양수 지원)
- **기존 차량 입력값**:
  - 기존 차량의 현재 중고 매각 가능 가격 (원)
  - 연비 및 에너지가격 (DB 과거 실적 기반 참고치 제안 + 사용자 직접 수정 확정)
  - 연간 예상 정비비, 연간 세금, 연간 보험료 (원)
  - 분석 기간 종료 시점($N$년 후)의 예상 잔존가치 (원)
- **교체 차량 입력값**:
  - 후보 차량 정보 (차량명, 연료, 구매가격, 정부/지자체 보조금, 취득 부대비용)
  - 연비 및 에너지가격
  - 연간 예상 정비비, 연간 세금, 연간 보험료 (원)
  - 분석 기간 종료 시점($N$년 후)의 예상 잔존가치 (원)
- **분석 결과 및 리포트**:
  - 유지 대안 현재가치 총비용 $PV_{\text{keep}}$
  - 교체 대안 현재가치 총비용 $PV_{\text{replace}}$
  - 두 대안의 현재가치 비용 차이 $\Delta PV = PV_{\text{replace}} - PV_{\text{keep}}$
  - 경제적 유리 대안 판정 및 상세 비용 구성표(초기비용, 에너지비, 정비비, 세금/보험료, 잔존가치 회수)
  - 비용 비교 시각화 차트 (누적 PV 및 카테고리별 비용 분해)
  - **학술/실무적 고지**: "본 결과는 입력된 가상의 가정 조건에 기초한 비용 비교이며, 미래 예측이나 절대적 최적 교체 시점을 의미하지 않습니다."

### 3.5 분석 이력 및 스냅샷 관리 (Analysis History)
- **분석 저장**: 분석명, 분석일시, 선택 차량, 모든 입력 파라미터 및 산출 결과를 JSON 스냅샷으로 영구 보관.
- **스냅샷 불변성**: 향후 차량 마스터 정보나 연료 단가가 변경되어도 과거 저장된 분석 결과는 변경되지 않음.
- **분석 복제(Clone) & 재분석**: 과거 분석을 불러와 조건을 일부 변경(예: 유가 상승, 주행거리 증가) 후 새 분석으로 저장.
- **CSV 내보내기**: 분석 이력 및 세부 비용 내역을 UTF-8 BOM 인코딩 CSV 파일로 다운로드.

### 3.6 데모 모드 및 시드 데이터
- 상단 네비게이션 또는 헤더에 **[데모 모드: 로컬 브라우저 저장소 사용 중]** 상태를 상시 표시.
- 최초 접속 시 5대의 가상 업무용 차량과 6개월 분량의 운행/주유/정비 시연 데이터 자동 생성.
- "모든 예시 수치는 과제 시연용 가상 데이터입니다" 안내 표기.
- 데이터 초기화(Reset to Demo) 기능 제공 (사용자 확인 팝업 포함).

## 4. 범위 (Scope)

| 영역 | 이번 단계 범위 (In-Scope) | 차기 배포 단계 (Out-of-Scope) |
| :--- | :--- | :--- |
| **인프라/배포** | 로컬 Vite 개발 서버 (`localhost:5173`) 실행 | GitHub 원격 푸시, Supabase 클라우드 프로젝트 생성, Vercel 웹 배포 |
| **데이터 계층** | Browser `localStorage` 기반 Repository 패턴 (인터페이스 분리 설계) | Supabase PostgreSQL 실제 REST API 및 RLS 연동 |
| **사용자 인증** | 단일 데모 유저 컨텍스트 (소유자 ID `demo-user-001` 고정) | Supabase Auth (이메일/소셜 로그인, JWT 토큰 관리) |
| **비용 분석** | 경제성공학 비용 현재가치(PV) 비교, 할인율 0% 및 양수 | 온실가스 배출량(LCA), 유류세 환급, 복잡한 세무 리스 계산 |
| **지능형 기능** | 정적 경제성 분석 알고리즘 (수식 기반) | API 키 필요 외부 LLM 생성형 AI 기능 |

## 5. 완료 기준 (Acceptance Criteria)

1. **문서화 완료**: `docs/prd.md`, `docs/design.md`, `docs/tasks.md`, `docs/rules.md`가 요구사항에 맞게 작성되어 있어야 함.
2. **동작 환경**: `npm run dev` 실행 시 에러 없이 로컬 웹 서버가 기동되고 UI가 렌더링되어야 함.
3. **5대 핵심 화면 구현**: 대시보드, 차량 관리, 운행/비용 기록(3개 탭), 경제성 비교, 분석 이력 화면이 온전히 동작해야 함.
4. **CRUD 및 무결성**:
   - 차량 추가/수정/삭제 가능 (차량번호 중복 방지, 종속 데이터 삭제 확인 다이얼로그).
   - 운행/주유·충전/정비 기록 각각의 추가/수정/삭제 가능.
   - 연료 종류에 따른 주유·충전 단위(`L`, `kWh`, `kg`) 자동 전환.
5. **계산 정확도 검증**:
   - 연간 에너지비용 계산식이 정확해야 함.
   - 할인율 0% 및 양수($i > 0$) 조건에서 균등 일련비용 현재가치 계수와 일시불 현가 계수가 오차 없이 계산되어야 함.
   - 기존차 유지 PV 및 신차 교체 PV 수식이 매몰비용을 배제하고 정확히 일치해야 함.
6. **데이터 영속성 및 스냅샷**:
   - 브라우저 새로고침 후에도 등록/수정된 데이터가 유지되어야 함.
   - 분석 저장 후 차량 정보를 수정해도 기저장된 분석 스냅샷은 변경되지 않아야 함.
   - 저장된 분석 복제 후 파라미터 수정이 정상 동작해야 함.
7. **CSV 내보내기**: 분석 이력 목록 및 세부 결과를 CSV로 다운로드할 수 있어야 함.
8. **UI/UX 가이드 준수**: 깔끔한 한국어 비즈니스 UI, 네이비(주조색)-청록(강조색), 천 단위 콤마 표기, 실시간 폼 유효성 검사 피드백 제공.
