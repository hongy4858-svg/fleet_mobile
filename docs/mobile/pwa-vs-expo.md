# PWA vs Expo 앱 비교 — 과제 회고

본 프로젝트는 웹 애플리케이션에 PWA를 추가한 단계(`pwa` 브랜치)와,
React Native / Expo로 모바일 앱을 별도 구현한 단계(`mobile` 브랜치)를 모두 거쳤습니다.
두 접근법을 실제 작업 경험을 바탕으로 비교합니다.

> **확인 상태 범례**
> ✅ 사용자 직접 확인 완료 / ⬜ 아직 확인 전 / — 해당 없음

---

## 비교표

| 비교 항목 | PWA | Expo 앱 | 내 의견 |
| :--- | :--- | :--- | :--- |
| **1. 개발에 걸린 시간** | 정확한 소요 시간 미기록. 기존 웹 코드(`src/`)를 그대로 유지하고 `manifest.json`, 최소 서비스 워커, 아이콘 파일, HTML 연결 코드만 추가했으므로 변경 범위가 작았다. | 정확한 소요 시간 미기록. React Native 화면 5종(`DashboardScreen`, `VehiclesScreen`, `LogsScreen`, `AnalysisScreen`, `HistoryScreen`), 네비게이터, 차트 컴포넌트 2종, 인증 모달을 처음부터 별도로 구현해야 했으므로 변경 범위가 훨씬 컸다. | 같은 기능 범위라면 PWA가 추가 개발 부담이 훨씬 적다. Expo는 UI를 처음부터 다시 짜야 하는 비용이 있다. |
| **2. 문서 수정량 (prd/design/tasks/rules)** | prd: 완료 기준 P1~P3 항목 추가. design: 변경 없음. tasks: PWA 작업 P1~P3 체크리스트 추가. rules: PWA 작업 규칙(§4) 추가. → **4개 문서 모두 소폭 보완** | prd: 사용 장면·기능군 구조 전면 개정. design: 기술 스택·화면 레이아웃·컴포넌트 전면 재작성. tasks: T1~T5 작업 구조 전면 재작성 + 변경 파일 테이블·휴대폰 확인 항목 추가. rules: React Native 컴포넌트 사용·Expo 패키지 규칙·앱 기능 불변 원칙 등 신규 항목 다수 추가. → **4개 문서 모두 대폭 개정** | Expo는 플랫폼 자체가 바뀌므로 문서도 그만큼 더 고쳐야 한다. 문서 작업량 차이가 개발 작업량 차이를 그대로 반영했다. |
| **3. 설치·실행 방법** | 브라우저에서 URL 접속 후 "홈 화면에 추가" 선택. 별도 앱 설치 과정 없음. 단, 홈 화면 추가 및 독립 창(standalone) 실행 여부는 ⬜ 아직 확인 전. | 개발 단계: `npx expo start` → Expo Go 앱에서 QR 코드 스캔 ✅ 사용자 확인 완료. 스토어 배포(EAS Build → App Store / Play Store)는 이번 단계에서 진행하지 않았다. | PWA는 URL만 있으면 되어서 배포가 간단하다. Expo Go는 개발 중 테스트에 편리하지만, 실제 배포는 스토어 심사가 필요하다. |
| **4. 화면 느낌·사용 편의성** | 웹 브라우저 UI 그대로. 사이드바·상단 헤더 레이아웃. 모바일 화면에서는 사이드바가 좁아 조작이 불편할 수 있다. | 하단 탭 5개·카드 목록·Modal 입력 폼 등 모바일 네이티브 패턴 적용. 스와이프·탭 제스처가 자연스럽다. ✅ Expo Go에서 실기기 실행 확인. | 모바일에서 직접 입력하는 용도에는 Expo가 훨씬 자연스럽다. 기존 웹 UI를 그대로 쓰는 PWA는 PC 브라우저 대상으로 설계된 레이아웃의 한계가 있다. |
| **5. 기기 기능 (카메라 등)** | 브라우저 API를 통해 일부 접근 가능(카메라: `getUserMedia`, 위치: `Geolocation API`)하지만 플랫폼별 지원 범위에 차이가 있다. 오프라인 동기화는 이번 프로젝트에서 구현하지 않았다. | Expo SDK를 통해 카메라·GPS·Push Notification 등 네이티브 기능에 접근 가능. 단, Expo Go에서 지원하지 않는 모듈은 Development Build가 필요하다. 카메라·GPS·오프라인 동기화는 이번 프로젝트에서 구현하지 않았다. | 현재 앱에서는 두 방식 모두 기기 고유 기능을 쓰지 않아 차이가 없다. 향후 카메라로 주유 영수증 촬영, GPS로 운행 경로 기록 같은 기능을 추가한다면 Expo가 유리하다. |
| **6. 업데이트 방법** | 서버 배포만으로 즉시 반영. 사용자가 별도 조작 없이 최신 버전을 받는다. | Expo Go 환경에서는 JS 번들이 자동 갱신된다. 스토어 배포 후에는 EAS Update(OTA)로 JS 변경을 즉시 배포할 수 있고, 네이티브 코드 변경 시에만 스토어 재심사가 필요하다. 단, 이번 단계에서는 스토어 배포를 하지 않았다. | 업데이트 편의성은 PWA가 더 단순하다. Expo도 OTA 업데이트로 커버 가능하지만 초기 배포 절차가 더 복잡하다. |
| **7. 우리 앱에 더 맞는 방식과 이유** | 사무실에서 PC 브라우저로 차량 목록 전체 조회, 경제성 비교 분석, CSV 내보내기 등 종합 관리 작업에 적합. | 운행 종료 직후 현장에서 주행거리·주유비를 바로 입력하거나, 출발 전 차량 상태를 빠르게 확인하는 용도에 적합. 하단 탭 탐색과 모달 입력 폼이 한 손 조작에 편리하다. | **두 가지를 함께 사용하는 구성이 가장 적합하다.** 운행 후 현장 입력에는 Expo 앱, 사무실의 종합 조회·경제성 분석·CSV 보고서 작성에는 웹/PWA를 사용하는 역할 분담이 이 프로젝트의 성격과 잘 맞는다. 같은 Supabase DB를 공유하므로 두 플랫폼의 데이터가 실시간으로 동기화된다. ✅ 모바일 운행 기록 → 웹 조회 확인 완료. |

---

## 요약

```
현장 입력 (차량 옆, 주유소, 정비소)
    → Expo 앱 (하단 탭·모달 입력, 실기기 Expo Go 확인 완료)
          ↕ 실시간 Supabase DB 동기화
사무실 종합 관리 (경제성 분석, 보고서, CSV)
    → 웹 / PWA (사이드바·전체 화면 레이아웃)
```

> **미확인 항목 안내**
> PWA의 홈 화면 추가·독립 창 실행, Expo 앱의 나머지 CRUD·분석 저장·복제·하단 탭 전환 등은
> 아직 실기기에서 확인하지 않았습니다. 위 표의 해당 항목은 ⬜로 표시했습니다.
